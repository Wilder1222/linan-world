## 二、P1 收口任务（当前优先级）

### P1-01｜中央人物档案复核

- 范围：`characters/central/` 12 份。
- 检查：每人的公开面具、未承认欲望、行为指纹、十个状态节点、七问、两条非中央关系。
- 必须补齐：每个状态的目标、误判、可观察动作、选择、具体代价、下一状态移交。
- 产物：逐人审读记录；若需改动，必须回写生成脚本或 Canon 源，不手改派生文件。
- 通过条件：不存在只写情绪形容词、不存在状态之间无因果跳跃。

### P1-02｜重要人物独立性复核

- 范围：`characters/important/` 24 份。
- 检查：职业流程、稳定欲望、阴影欲望、代价、幽默/现代情绪入口，以及“不替代中央人物功能”。
- 产物：A 级人物独立性矩阵；标记其影响的中央人物、生活圈和关系 ID。
- 通过条件：每名 A 级人物至少拥有一项不能由中央人物替代的职业/关系功能。

### P1-03｜常驻人物抽样与生活真实性

- 范围：`characters/recurring/` 48 份，覆盖每个生活圈至少 2 人。
- 检查：年龄推定、家庭结构、收入压力、首次日常、职业能力展示、终局公共回响。
- 产物：B 级抽样审读表；问题集中回写 `materialize_recurring_profiles.py` 或源表。
- 通过条件：不把 B 人物写成只为主角递线索的“功能群众”。

### P1-04｜关系证据绑定

- 范围：`characters/relations/core/` 17 份。
- 对每个关系的七维状态与八个快照补入：具体场次候选、物件、台词/潜台词、空间位置、可观察动作、连续性影响。
- 暂不要求锁定最终集号；先建立可追溯证据槽位，待 Season Gate 再绑定最终集/章。
- 通过条件：关系不再只是“好感度”，且至少保留一组混合情感与未解决问题。

### P1-05｜情感脊柱压力测试

- 范围：6 条脊柱 × 6 篇 = 36 个状态。
- 检查：每篇是否有混合情感、主动选择、不可逆代价、关系余波；是否避免自动和解。
- 产物：`qa/emotional-spines.json` 的人工复核标记和变更日志。
- 通过条件：任一状态都能回答“谁想要什么、谁阻止、谁选择、谁付账、下一篇因此改变什么”。

### P1-06｜U/BG 边界审计

- `qa/unit-slots.json`：保持 120 个槽位、22 个 POV 槽位、候选池与自然回访指标；不提前赋予唯一主线身份。
- `qa/background-usage.json`：保持 300 个原型、15 个生态、地点/时段/劳动状态字段；Episode Gate 前允许使用数组为空，但禁止静态装饰化。
- 通过条件：任何 U/BG 的未来绑定都有 Gate 依赖和回溯 ID。

### P1-07｜Character Foundation Gate

- 先运行：

  ```powershell
  python scripts/audit_character_content.py
  python scripts/validate_characters.py --stage foundation --strict
  python scripts/validate_project.py --scope character-foundation --strict
  python scripts/validate_project.py --scope canon --strict
  python -m unittest discover -s tests -q
  git diff --check
  ```

- 再将人工清单全部勾选，生成 `qa/gates/character-foundation-gate.json`。
- Gate 关闭条件：机器校验通过、人工审读无阻断项、所有变更已由源数据/脚本可再生成。

## 三、P2 Season Gate 任务（P1 关闭后启动）

### P2-01｜36 集因果账本

为每集建立一行机器可读记录：`episode_id / central_question / city_evidence / relationship_choice / profession_action / reveal_seed / misread / recheck / reframe / irreversible_cost / tail_hook / next_chase`。

验收：每集至少一个城市证据、一个关系选择、一个职业动作；每次翻转都有“播种 → 误读 → 复核 → 重义”。

### P2-02｜AI 短剧单章规格

默认每章 2–3 分钟，采用：

1. 0–10 秒冷钩子；
2. 10–45 秒目标与阻力；
3. 45–100 秒证据/关系动作；
4. 100–150 秒选择与代价；
5. 最后 10–20 秒尾钩。

每章只允许一个首要 POV、一个首要叙事功能和一个状态变化。尾钩轮换为物证、误判、越界、制度反应、生活异常、倒计时六类，避免连续同型。

### P2-03｜生活活动与情感推进

将夜市、茶坊、瓦舍、游湖、灯会、相扑、船运、书坊、家庭饮食、调香、修船等活动逐项登记：人物目标、现场阻力、关系变化、线索变化、选择、状态移交、连续性成本。

活动不能只做风俗展示，必须至少推进一条关系或改变一条线索。

### P2-04｜幽默与语域控制

沿用 `story/03-humor-and-register-standard-v1.md`：冷笑话、错位反问、物件笑点、黑色幽默和“抢先一步”优先；热梗只做宋代语境转译。

每个笑点登记说话者意图、潜台词、他人反应和笑意收回；不得消解死亡、创伤、洪灾和制度代价。

### P2-05｜Season Gate

- 产物：36 集因果账本、季级悬疑/翻转矩阵、活动使用表、幽默使用表、U 槽位候选分配表。
- 通过条件：所有集尾钩能回指下一集追问；U 仍可替换且未被写死；生活活动与主线因果互相支撑。

## 四、P3 Episode / AIGC 任务（Season Gate 关闭后启动）

每集固定流水线：

`Narrative Canon → Character State → Relationship State → Scene Goal → Emotion/Action → Dialogue → Blocking → Storyboard → AIGC → Continuity QA → Story QA`

### P3-01｜逐集生产包

每集必须有正式剧本、逐场表演卡、关系 Delta、服化道/信息连续性账本、镜头表、静帧 Prompt、视频 Prompt、配音 Prompt。

### P3-02｜试点集

先完成 E01–E03 作为生产试点，验证：2–3 分钟章节节奏、钩子密度、角色稳定性、宋代生活活动、幽默边界和 AIGC 连续性；通过后再批量扩展 E04–E36。

### P3-03｜Episode Gate

每集九项 Gate：人物、情绪、动作、行为、关系、服装/道具、镜头、AIGC、故事逻辑，单项低于 90 不进入成片生成。
