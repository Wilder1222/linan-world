# 《临安春信》人物档案 Schema v1

本文件是 P1 Character Foundation 的唯一字段约束。人物事实写在独立档案，`qa/character-roster.json` 只登记稳定 ID、档位、预算和路径；入口索引不得复制另一套事实。

## 1. 文件格式

每份命名人物档案必须使用 Python `tomllib` 可解析的 TOML front matter：

```toml
+++
id = "CHR-L1-01"
tier = "L1"
name = "沈蘅"
aliases = []
age_y0 = 22
occupation = "沈家香铺调香师、辨货人"
residence = "鹤鸣巷沈家香铺后院"
economic_source = "香铺调香、辨货与家业分成"
pov_budget = 52
minimum_episode_coverage = 24
status = "FOUNDATION-DRAFT"
+++
```

front matter 只能包含以下 11 个键，不得使用 YAML、重复键或未声明字段：

`id`、`tier`、`name`、`aliases`、`age_y0`、`occupation`、`residence`、`economic_source`、`pov_budget`、`minimum_episode_coverage`、`status`。

## 2. 正文必备区块

L1/L2/L3 与 A1/A2/A3 必须具备全部区块；B 使用“基础状态”简版；U 在 Foundation 阶段只写席位，不伪造全年人物弧。

### 身份与外在

- 籍贯与阶层
- 职业流程：输入、工具、步骤、常见错误、身体痕迹
- 外貌与体态稳定锚点
- 年龄/职业留下的可见痕迹
- 四季服装与随身物

### 内在与行为

- 公开身份、隐藏经历、他人误解
- 有意识欲望、真实需要、恐惧、价值观、缺点、底线、秘密
- 语言节奏、口头习惯、沉默方式
- 默认姿态、视线顺序、呼吸、手部动作、重心、关心动作
- 能力边界、禁止突然获得的能力、常见错误反应

### 现实与关系

- 一日作息、收入来源、债务、照料责任
- 至少两条不经过 L1—L3 的关系（L1—L3 人物可作为额外关系，但不能充数）
- 每条关系写表面行为、自觉动机、未承认动机和情感债务

### 坚守七问

1. 最想保护什么？
2. 这种坚守为什么形成？
3. 在保护它时伤害过谁？
4. 两件都正确的事冲突时选择什么？
5. 为此具体放弃什么？
6. 谁会因此误解、怨恨或离开？
7. 即使没有回报，是否仍承认这个选择属于自己？

### 状态与选择链

L/A 档必须有十个稳定字段：`Y-13`、`Y0-OPEN`、`ARC1-END`、`ARC2-END`、`ARC3-END`、`ARC4-END`、`ARC5-END`、`ARC6-END`、`ENDING`、`Y+1`。每个检查点至少写目标、误判、选择、代价、关系变化和状态移交；`ARC6-END` 与 `ENDING` 不得合并。

B 档必须有 `Y0-OPEN`、首次日常、终局职业回响、`ENDING` 四项；U 档 Foundation 阶段只登记首事件、余波与回场预留。

## 3. 生产级行为要求

- 情绪必须落成可观察的脸、呼吸、视线、手、重心、距离、行动和余波，不用“她很难过”替代表演。
- 职业能力只能来自档案中已经展示的劳动过程；终局回响必须有前置技能痕迹。
- 幽默、宋代活动和现代观众可识别的生活兴趣必须改变关系、线索或选择，不能只是资料展示。
- 不得使用隐藏血统、梦兆、全知闪回、突然武力升级或一次道歉恢复全部信任。
- 任何实际母集、微短章绑定、U 实际 POV 和 BG 实际使用都由 Season/Episode/Final Gate 写入，不能在 Foundation 档案中冒充已完成。
